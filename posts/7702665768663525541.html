一句话总结

这条视频用“新员工 Claude Code 的一天”串起 9 个 AI 黑话：LLM 是大脑、Token 是计价单位、Prompt 是指令、Context 是办公桌、API 是接口、MCP 是统一插口、Agent 是干活的员工、Skill 是岗位手册、Workflow 是流水线；最后给了一个省 Token 的分工建议。

视频讲了什么

1）LLM：大语言模型，AI 的“大脑”。视频举例 Claude Code 用 Claude，Codex 用 GPT；模型是能力底座，不是产品本身。

2）Token：AI 读写的最小单位，一个汉字大约一个 Token，按它计费。它既是成本单位，也是上下文容量的单位。

3）Prompt：给 AI 的指令。说清楚“给谁、要什么、什么格式”，结果才准；模糊的指令会得到模糊的输出。

4）Context：上下文，相当于 AI 的办公桌。桌上堆满东西就会忘事、降智；聊太长就新开窗口，把当前任务重新讲清楚。

5）API：软件对外留的接口。每家接法不同，但作用都是让程序调用模型或其他服务。

6）MCP：统一插口，像 USB-C。接上飞书这类系统后，AI 可以直接找文档、发消息，不用为每个系统单独写一套对接。

7）Agent：会自己拆任务、选工具、干到底的 AI。只会一问一答的聊天机器人，不算 Agent。

8）Skill：岗位手册。平时只占“书名”的位置，用到才翻开；把经验写成 Skill，Agent 就能按步骤执行一类任务。

9）Workflow：工作流。步骤定死、每天照跑的流水线，适合稳定、重复的流程。

最后给了一个实用建议：做决策、定方案交给贵模型，执行类工作交给便宜模型；不是所有步骤都值得用最贵的模型。

关键点

  • LLM vs Agent：模型是大脑，Agent 是能拆任务、用工具、干到底的员工。
  • Token 双属性：既是计费单位，也是上下文容量单位。
  • Prompt 要具体：对象、目标、格式说清楚，输出才稳定。
  • Context 像办公桌：堆满会降智，长任务要新开窗口或压缩。
  • MCP 是统一插口：减少每个系统单独对接的成本。
  • Skill vs Workflow：Skill 是一类任务的做法，Workflow 是固定步骤的流水线。
  • 省 Token 分工：贵模型做决策，便宜模型做执行。

适合谁看

刚接触 AI、被 LLM/Token/MCP/Agent 这些词绕晕的人；以及想分清“聊天工具”和“能干活的工作流”的人。视频是名词科普，每个概念的具体实现还需要结合实际工具。
